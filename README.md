# TRCA Online Assessment — ชุดไฟล์สมบูรณ์ (รุ่นแอป 3.2.0)

ระบบเก็บข้อมูลออนไลน์ของแบบประเมินสมรรถนะการวิจัยของครู (Teacher Research Competency Assessment)
ครอบคลุม 3 มิติ รวม 68 ข้อ ข้อคำถามเป็นความเรียง ตรงกับเอกสาร `TRCA_ฉบับสมบูรณ์สำหรับตรวจคุณภาพ.docx`
ปรับปรุง 7 ตุลาคม 2569 (รุ่นเครื่องมือ `TRCA-PROSE-20261007-R1`) ให้ผลลัพธ์ในโครงสร้างเดียวกับไฟล์ `TRCA_KSA_Simulated_N350_v2.xlsx`
และแปลงเป็นแฟ้มสำหรับ ACER ConQuest 2.0 ได้โดยตรง เมื่อผู้ตอบส่งแล้วจะดูเฉลยและเหตุผลรายข้อได้

## ติดตั้งบน GitHub Pages (ฉบับสั้น)

ชุดไฟล์นี้ครบทุกไฟล์แล้ว ใช้ได้ทั้งตั้งใหม่และอัปเดตทับของเดิม ผู้ใช้ตั้งค่าเพียงไฟล์เดียวคือ `config.js`

1. **ใส่ลิงก์ปลายทาง** เปิดไฟล์ `config.js` ด้วย Notepad วางลิงก์ Web app ของ Apps Script (ลงท้าย `/exec`) ระหว่างเครื่องหมาย `' '` ที่บรรทัด `endpoint` แล้ว Save
2. **อัปโหลดขึ้น GitHub** เปิด repository แล้วกด **Add file → Upload files** เปิดโฟลเดอร์ที่แตกซิปแล้ว กด Ctrl+A เลือก **ทุกอย่างข้างใน** (ไม่ใช่ตัวโฟลเดอร์แม่) ลากไปวางในหน้า Upload รอจนครบ แล้วกด **Commit changes**
3. **เปิด GitHub Pages** (ทำครั้งเดียว) Settings → Pages → Build and deployment → Source: **Deploy from a branch** → Branch: **main** และโฟลเดอร์ **/ (root)** → Save รอ 1–5 นาที
4. **ตรวจการติดตั้ง** เปิด `https://<ชื่อผู้ใช้>.github.io/<ชื่อ repository>/tools/check.html` กด Ctrl+Shift+R ต้องผ่านทุกข้อ ถ้ามีข้อใดไม่ผ่านจะบอกวิธีแก้ไว้ใต้ข้อนั้น
5. **ฝั่ง Google** ถ้ายังไม่เคยทำหรือเพิ่งอัปเดต `server/Code.gs` ให้วางไฟล์ใน Apps Script รัน `setupSheets()` แล้ว Deploy → Manage deployments → ไอคอนดินสอ → Version: **New version** → Deploy
6. **ทดสอบหนึ่งรอบ** ตอบจนส่งสำเร็จ ตรวจว่ามีแถวใหม่ในชีต แล้วลบแถวข้อมูลทดสอบก่อนแจกครู

**อาการที่พบบ่อย**

| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| เปิดแล้วเห็นแต่ชื่อหัวเรื่องบรรทัดเดียว ไม่มีสี ไม่มีข้อ | โฟลเดอร์ `css` และ `js` ไม่ได้อยู่ข้าง `index.html` (มักซ้อนอยู่ในโฟลเดอร์อื่น) เปิด `tools/check.html` ถ้าเปิดไม่ได้ แปลว่าโครงสร้างผิดทั้งชุด ให้ลบไฟล์ใน repository แล้วอัปโหลดใหม่ตามข้อ 2 |
| หน้าแรกมีกรอบแดง “ระบบรับข้อมูลยังตั้งค่าไม่เสร็จ” | `endpoint` ใน `config.js` ว่างหรือรูปแบบไม่ถูกต้อง |
| ส่งข้อมูลแล้วขึ้น Failed to fetch | ลิงก์ลงท้าย `/dev` หรือสิทธิ์ไม่ใช่ Anyone หรือยังไม่ Deploy New version เปิด `tools/check.html` ดูข้อ 4 |
| ส่งแล้วขึ้นว่าเป็นฉบับเก่า | `Code.gs` ใน Apps Script ยังไม่ใช่รุ่นเดียวกับเว็บ วางทับแล้ว Deploy New version |
| แก้ไฟล์แล้วหน้าเว็บยังเหมือนเดิม | GitHub Pages เก็บแคช 5–10 นาที รอแล้วกด Ctrl+Shift+R |

## โครงสร้างข้อมูลที่ระบบผลิต

| มิติ | รหัสข้อ | ตัวเลือก | คะแนน | โมเดลการวัด |
|---|---|---|---|---|
| K ความรู้ | K01–K28 | 4 | 0 หรือ 1 | Rasch แบบสองค่า |
| S ทักษะ | S01–S20 | 4 | 0–3 | Partial Credit Model |
| A คุณลักษณะ | A01–A20 | 4 | 0–3 | Partial Credit Model |

**กฎการตอบที่ระบบบังคับใช้: ทุกข้อต้องตอบ**

| สถานการณ์ | ระบบทำอย่างไร |
|---|---|
| ไม่มีตัวเลือก “ไม่ประสงค์ตอบข้อนี้” | ทุกข้อ ทุกมิติ ต้องเลือกตัวเลือก 1–4 ก่อนส่ง |
| ข้อที่ยังว่างตอนทบทวนก่อนส่ง | ส่งไม่ได้ แตะหมายเลขข้อเพื่อกลับไปตอบ |
| มิติ S | ไม่มีปุ่ม “ข้ามไปก่อน” ต้องตอบข้อนี้จึงไปข้อถัดไปได้ ไม่มีการข้ามทั้งตอน |
| มิติ K และ A | ข้ามไปก่อนแล้วกลับมาตอบทีหลังได้ แต่ต้องตอบครบทุกข้อก่อนส่ง |
| ผู้ตอบไม่ต้องการตอบข้อใด | ยุติการทำได้ทุกเมื่อ หากยุติก่อนกดส่ง คำตอบอยู่ในเครื่องผู้ตอบเท่านั้น ไม่ถูกส่งถึงผู้วิจัย |

**ข้อควรทราบ** ข้อ 5.2 ของเอกสารฉบับสมบูรณ์เขียนว่าผู้ตอบไม่ประสงค์ตอบบางข้อได้ และข้อ 9.2 กำหนดรหัส D สำหรับกรณีนี้
ระบบเว็บนี้ไม่มีทางเลือกดังกล่าว หากคำชี้แจงโครงการหรือเอกสารขอรับรองจริยธรรมระบุว่าผู้ตอบข้ามรายข้อได้
ควรแก้ให้ตรงกัน หรือกำหนดช่องทางอื่น เช่น แจ้งผู้วิจัยโดยตรง

**ฝั่งรับข้อมูล (Code.gs) ตรวจซ้ำอีกชั้น** ปฏิเสธการบันทึกหากข้อใดว่าง ค่าคำตอบอยู่นอก 1–4 หรือคะแนนไม่สอดคล้องกับคำตอบ
รวมถึงข้อมูลที่มีค่า D หรือ M จากหน้าเว็บรุ่นเก่าที่เคยมีปุ่มไม่ประสงค์ตอบ (ผู้ส่งจะได้ข้อความให้รีเฟรชหน้าและตอบข้อนั้น)

**ระบบเก็บทั้งหมายเลขตัวเลือกดิบและคะแนน** ชีต `Raw` เก็บหมายเลขตัวเลือกที่ผู้ตอบเลือกจริง
ส่วนชีต `TRCA_Data` เก็บคะแนนที่แปลงแล้ว หากภายหลังต้องแก้เฉลยหรือปรับพื้นที่ผลลัพธ์
จะให้คะแนนใหม่จากข้อมูลเดิมได้โดยไม่ต้องเก็บข้อมูลซ้ำ

## รุ่นเครื่องมือ (Instrument version)

ทุกการส่งข้อมูลมีรหัสรุ่นเครื่องมือ `TRCA-PROSE-20261007-R1` กำกับ (คอลัมน์ `Instrument` ในชีต Raw และ Person_Info)
เพราะข้อความโจทย์และลำดับตัวเลือกของแต่ละรุ่นต่างกัน คำตอบต่างรุ่นจึงรวมเป็นชุดเดียวกันไม่ได้
(ตอนที่ 6.2 ของ TRCA ฉบับความเรียง)

- ค่าต้องตรงกันสามที่: `INSTRUMENT_VERSION` ใน `js/items.js` · `ACCEPTED_INSTRUMENT` ใน `server/Code.gs` · `EXPECTED_INSTRUMENT` ใน `tools/export.html`
- หน้าเว็บฉบับเก่าที่ยังค้างในเครื่องครู จะส่งข้อมูลเข้าไม่ได้ ระบบแจ้งให้รีเฟรชหน้า คำตอบที่ค้างในเครื่องจากฉบับเก่าจะไม่ถูกนำมาต่อกับฉบับนี้
- เมื่อแก้ข้อความโจทย์หรือตัวเลือกข้อใดภายหลัง ต้องเปลี่ยนรหัสรุ่นทั้งสามที่ แล้วอัปโหลดและ Deploy ใหม่ จากนั้นข้อมูลรุ่นเก่าให้เก็บแยกไว้ ไม่นำมาวิเคราะห์รวม
- `tools/export.html` จะเตือนหากข้อมูลที่วางมีหลายรุ่นปนกัน

### การอัปเดตจากระบบรุ่นก่อน

ใช้ชุดไฟล์สมบูรณ์นี้อัปโหลดทับทั้งชุดตามหัวข้อ “ติดตั้งบน GitHub Pages (ฉบับสั้น)” ข้างบน ไม่ต้องเลือกอัปโหลดทีละไฟล์
สิ่งที่ต้องทำเพิ่มมีสองอย่าง

1. สำรอง Google Sheet (File → Download → Excel) แล้วลบแถวข้อมูลทดลองจากฉบับเก่าในชีต `TRCA_Data`, `Raw`, `Person_Info`, `Conflicts` (ข้อมูลต่างรุ่นรวมกันไม่ได้) ห้ามลบแถวหัวตาราง
2. ลิงก์ endpoint ที่เคยอยู่ใน `index.html` ย้ายมาอยู่ใน `config.js` แล้ว ต้องวางลิงก์เดิมใน `config.js` อีกครั้งหนึ่ง (ไฟล์ `index.html` ใหม่ไม่มีลิงก์อยู่ภายใน)

## การติดตั้ง

### ขั้นที่ 1 เตรียมปลายทางรับข้อมูล

1. สร้าง Google Sheet ใหม่ ตั้งชื่อ `TRCA_Responses`
2. เมนู **ส่วนขยาย → Apps Script** วางเนื้อหาของ `server/Code.gs` ทับโค้ดเดิม
3. รันฟังก์ชัน `setupSheets()` หนึ่งครั้งเพื่อสร้างหัวตารางสามชีต
4. กด **Deploy → New deployment → Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
5. คัดลอก Web app URL ที่ได้

### ขั้นที่ 2 ตั้งค่าหน้าเว็บ

เปิดไฟล์ `config.js` แล้ววาง URL ลงในบรรทัด `endpoint`

```js
window.TRCA_CONFIG = {
  endpoint: 'https://script.google.com/macros/s/xxxxx/exec',
  revealAnswers: true
};
```

หากเว้นว่างไว้ หน้าแรกจะแสดงกรอบแดงเตือนว่ายังตั้งค่าไม่เสร็จ และผู้ตอบจะส่งข้อมูลไม่ได้ (ระบบให้บันทึกคำตอบเป็นไฟล์แทน)
`index.html` และ `results.html` อ่านค่าจากไฟล์นี้ไฟล์เดียว

### ขั้นที่ 3 นำขึ้นเว็บ

ใช้บริการที่รองรับเว็บแบบสแตติกและฟรี เช่น GitHub Pages, Netlify หรือ Cloudflare Pages
อัปโหลดทุกไฟล์ในชุดนี้แล้วส่งลิงก์ให้ครูผู้ตอบ (ใช้ GitHub Pages ตามขั้นตอนฉบับสั้นด้านบน)

**ต้องเปิดผ่าน HTTPS เท่านั้น** เพราะ `index.html` ใช้ JavaScript Module
การเปิดไฟล์ตรงจากเครื่องด้วย `file://` จะถูกเบราว์เซอร์ปิดกั้น
หากต้องการทดสอบในเครื่อง ให้รัน

```bash
cd โฟลเดอร์ที่มี index.html
python3 -m http.server 8000
```

แล้วเปิด `http://localhost:8000`

## เฉลยและเหตุผลสำหรับผู้ตอบ

หลังส่งแบบประเมินสำเร็จ หน้าจบมีปุ่ม “ดูเฉลยและเหตุผล” แสดงรายข้อแยกเป็น 3 ตอน (แตะข้อเพื่อขยาย)

| ตอน | สิ่งที่แสดง |
|---|---|
| 1 ความรู้ (K) | ตัวเลือกที่ท่านเลือก ตัวเลือกที่เป็นเฉลย ✓/✗ และเหตุผล พร้อมสรุป “ตอบถูก X จาก 28 ข้อ” |
| 2 ทักษะ (S) และ 3 คุณลักษณะ (A) | คะแนน 0–3 ของทั้ง 4 ตัวเลือกพร้อมเหตุผลรายตัวเลือก ระบุตัวเลือกที่ท่านเลือก สรุปจำนวนข้อตามคะแนนที่ได้ ข้อความกำกับว่าไม่ใช่ระดับสมรรถนะ |

เหตุผลทั้งหมดมาจากเอกสารฉบับผู้วิจัยโดยตรง (ข้อความ “เหตุผล” ของ K และเหตุผลรายระดับของ S กับ A)

**ข้อควรระวังเรื่องเฉลยรั่ว** เอกสารฉบับสมบูรณ์ข้อ 5.1 ให้ซ่อนเฉลยจากสิ่งที่ผู้ตอบเห็นระหว่างตอบ ระบบนี้แสดงเฉลย
เฉพาะหลังส่งแล้ว (คำตอบถูกล็อกและบันทึกแล้ว) แต่ครูที่ทำเสร็จก่อนอาจบอกเฉลยแก่ผู้ที่ยังไม่ได้ทำ
ซึ่งกระทบข้อมูลของผู้ตอบรายถัดไปโดยเฉพาะมิติ K และเฉลยอยู่ในไฟล์ `js/items.js` ที่เบราว์เซอร์ดาวน์โหลด
ผู้ที่เปิดดูซอร์สจะเห็นได้ก่อนตอบ

**ปิดการแสดงเฉลยระหว่างเก็บข้อมูล** เปิด `config.js` แล้วเปลี่ยน `revealAnswers` เป็น `false`

```js
window.TRCA_CONFIG = {
  endpoint: 'https://script.google.com/macros/s/xxxxx/exec',
  revealAnswers: false
};
```

เมื่อปิด หน้าจบจะแจ้งว่าผู้วิจัยจะแจ้งเฉลยภายหลัง เมื่อเก็บข้อมูลครบให้เปลี่ยนกลับเป็น `true` ครูที่เปิดลิงก์เดิมในอุปกรณ์เดิม
(ที่เก็บคำตอบไว้) จะเห็นปุ่มดูเฉลยโดยไม่ต้องทำใหม่ ส่วนอุปกรณ์อื่นที่ไม่มีคำตอบเก็บไว้ดูเฉลยเทียบกับคำตอบของตนไม่ได้

## การแสดงผลคะแนนแก่ผู้ตอบ

ระบบแสดงผลเป็น 2 ช่วง เพราะคะแนนดิบตีความระดับสมรรถนะโดยตรงไม่ได้ ต้องผ่านการวิเคราะห์ราสช์ร่วมกับผู้ตอบทั้งหมดก่อน

**ช่วงที่ 1 ทันทีหลังส่ง** หน้า `index.html` แสดงเพียงสรุปจำนวนข้อที่ตอบต่อมิติ ไม่แสดงคะแนนหรือระดับ พร้อมรหัสอ้างอิงให้ครูเก็บไว้ตรวจผลภายหลัง

**ช่วงที่ 2 หลังวิเคราะห์เสร็จ** ครูกลับมาตรวจผลได้เองที่หน้า `results.html` โดยกรอกรหัสอ้างอิง ขั้นตอนที่ผู้วิจัยต้องทำก่อนเปิดให้ตรวจผล

1. วิเคราะห์ข้อมูลทั้งหมดด้วย ACER ConQuest 2.0 ตามที่อธิบายไว้ก่อนหน้า ได้ไฟล์ `.eap` ที่มีค่า θ และ SE รายบุคคลทั้งสามมิติ
2. คำนวณคะแนนมาตรฐาน T = 50 + 10θ และกำหนดระดับ 0–4 ตามขอบเขตเกณฑ์ที่ได้จากการวิเคราะห์
3. เปิด Google Sheet ไปที่แท็บ **`Results`** กรอกข้อมูลแต่ละแถวตามรหัสผู้ตอบ (คอลัมน์ ID ต้องตรงกับที่ครูได้รับ) ใส่ค่า `Theta_K, SE_K, T_K, Level_K` และเช่นเดียวกันสำหรับ S และ A
4. เมื่อกรอกครบทุกคนแล้ว ไปที่แท็บ **`Config`** เปลี่ยนค่าในคอลัมน์ Value ของแถว `ResultsPublished` จาก `FALSE` เป็น `TRUE`
5. ตั้งแต่นั้นครูจะกดปุ่ม "ตรวจสอบผลภายหลัง" จากหน้าจบ หรือเข้า `results.html` โดยตรง แล้วกรอกรหัสของตนเพื่อดูผลได้ทันที

**ก่อนตั้งค่า `ResultsPublished` เป็น `TRUE`** ทุกคนที่ตรวจสอบจะเห็นข้อความ "ยังไม่เปิดให้ตรวจสอบผล" เสมอ ไม่ว่าจะกรอกรหัสใด จึงปลอดภัยจากการเผยแพร่ผลก่อนวิเคราะห์เสร็จหรือก่อนตรวจทานความถูกต้อง

**คำอธิบายระดับที่แสดงให้ครูเห็น** ดึงมาจากกรอบการประเมินที่ใช้สร้างแผนที่โครงสร้างของเครื่องมือนี้โดยตรง (ฝังไว้ในไฟล์ `results.html` แล้ว) หากภายหลังปรับถ้อยคำกรอบการประเมิน ต้องแก้ในไฟล์นี้ให้ตรงกันด้วย

## การนำข้อมูลไปวิเคราะห์

1. เปิด `tools/export.html`
2. คัดลอกทั้งชีต `TRCA_Data` จาก Google Sheet มาวางในช่องแรก
3. คัดลอกทั้งชีต `Person_Info` มาวางในช่องที่สอง เพื่อเติมตัวแปรจัดกลุ่มสำหรับการวิเคราะห์ DIF
4. กด **ตรวจข้อมูลและสร้างแฟ้ม** ระบบจะรายงาน
   - จำนวนผู้ตอบและช่องว่างรายมิติ (ข้อมูลจากเว็บไม่ควรมีช่องว่าง)
   - รุ่นเครื่องมือของข้อมูลที่วาง และเตือนหากปนกันหลายรุ่น
   - จำนวนครูที่มีช่องว่างเกินร้อยละ 10 ของแต่ละมิติ
   - ข้อที่มีผู้ตอบบางระดับคะแนนน้อยกว่า 3 คน ซึ่งจะประมาณค่าขีดจำกัดไม่ได้
   - ข้อที่มีช่องว่างเกินร้อยละ 10 (ทุกมิติ)
5. ดาวน์โหลด `trca.dat` แฟ้ม `.lab` และแฟ้มคำสั่ง `.cqc` ไปใช้กับ ACER ConQuest 2.0

รูปแบบคอลัมน์ของ `trca.dat` กว้าง 79 อักขระคงที่

| คอลัมน์ | เนื้อหา |
|---|---|
| 1–6 | รหัสผู้ตอบ |
| 8 | วิทยฐานะ |
| 9 | ขนาดโรงเรียน |
| 10 | ประสบการณ์วิจัย |
| 12–39 | K01–K28 |
| 40–59 | S01–S20 |
| 60–79 | A01–A20 |

ใช้เครื่องหมาย `.` แทนข้อมูลขาดหาย และ**ต้องไม่ประกาศอักขระนี้ในคำสั่ง `Codes`**
มิฉะนั้นช่องว่างจะกลายเป็นคะแนนต่ำสุดทันที

## สิ่งที่ระบบตั้งใจไม่ทำ

**ไม่แสดงคะแนนให้ผู้ตอบ** เพราะคะแนนดิบยังไม่ผ่านการแปลงเป็นค่าความสามารถ จึงตีความโดยตรงไม่ได้
และการแสดงคะแนนระหว่างเก็บข้อมูลอาจทำให้ครูพูดคุยกันจนกระทบคำตอบของผู้ตอบรายถัดไป

**ไม่สลับลำดับตัวเลือกรายบุคคล** เพราะลำดับตัวเลือกในคลังข้อคำถามผ่านการสลับมาแล้วครั้งหนึ่งให้สมดุล
และต้องตรงกับฉบับกระดาษเพื่อให้เปรียบเทียบผลกันได้

**ไม่เก็บชื่อและชื่อโรงเรียน** ใช้เพียงรหัสอ้างอิงที่ระบบสร้างขึ้น

## ข้อควรระวัง

**ตรวจไฟล์ `js/items.js` ก่อนใช้งานจริง** ลำดับตัวเลือกกับค่า `scores` ผูกกันแบบตำแหน่งต่อตำแหน่ง
หากสลับลำดับตัวเลือกโดยไม่แก้ `scores` ให้ตรงกัน คะแนนจะผิดทั้งชุดโดยไม่มีข้อความเตือน

**ทดสอบว่าส่งไม่ได้เมื่อยังมีข้อว่าง ก่อนเก็บข้อมูลจริง** โดยตอบไม่ครบแล้วไปหน้าทบทวน ปุ่ม “ส่งแบบประเมิน” ต้องกดไม่ได้
และมิติ S ต้องไม่มีปุ่ม “ข้ามไปก่อน”

**ตรวจหน้าเฉลยก่อนแจกครู** ตอบด้วยตัวเลือกที่ทราบคะแนน เช่น เลือกตัวเลือกที่เป็นเฉลยทุกข้อใน K แล้วดูว่าสรุปขึ้น “ตอบถูก 28 จาก 28 ข้อ”

**เฉลยและเกณฑ์คะแนนอยู่ใน `js/items.js` ที่เบราว์เซอร์ดาวน์โหลด** ผู้ที่เปิดดูซอร์สของหน้าเว็บจะเห็นเฉลยมิติ K ได้
ยอมรับได้เมื่อแจ้งว่าแบบประเมินไม่มีผลต่อครู แต่ควรระบุเป็นข้อจำกัดของการเก็บข้อมูล หากต้องการปิดจุดนี้ ต้องย้ายการให้คะแนนไปไว้ฝั่ง Apps Script

**ทดสอบกับครูจริงอย่างน้อย 5 คนก่อนเปิดใช้** เพื่อดูเวลาที่ใช้จริงและอัตราการตอบไม่จบ

**สำรองข้อมูลระหว่างเก็บ** ดาวน์โหลด Google Sheet เป็นไฟล์ Excel อย่างน้อยสัปดาห์ละครั้ง
